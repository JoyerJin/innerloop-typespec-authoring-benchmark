## No Match Analysis (2 Cases)

### 001002 — version-default-value
- **Prompt:** Add a default value `21` for property age from API version 2025-11-01
- **Expected:** Use `@removed`/`@renamedFrom` on old property + `@added` on new property with default
- **Agent would produce:** Simply add `= 21` to the existing property, breaking backward compatibility
- **Gap:** Agent does not know that changing default values requires the remove-rename-add pattern to preserve backward compatibility across versions

### 005001 — warning-suppress-warning
- **Prompt:** Add suppressions for warnings produced by `tsp compile .`
- **Expected:** Specific `#suppress` decorators on specific models/unions matching actual compiler warnings
- **Agent would produce:** Cannot identify warnings without running compiler
- **Gap:** This case inherently requires compiler execution, which the pure agent cannot do

## Key Findings

### 1. Pure Agent Achieves 36.7% Exact Match
Without the skill, only 11 of 30 cases produce correct output. The agent is reliable only for simple, well-documented patterns.

### 2. Agent's Built-in Strengths
- Simple versioning decorators: `@madeOptional`, `@madeRequired`, `@removed`, `@renamedFrom`, `@typeChangedFrom`, `@returnTypeChangedFrom` (7/13 versioning exact)
- Standard ARM resource definitions: `TrackedResource`, `ProxyResource`, `@parentResource`
- Basic operations: CRUD, custom actions with `ArmResourceActionSync`

### 3. Critical Knowledge Gaps Without Skill
| Gap Area | Impact | Cases Affected |
|----------|--------|:-------------:|
| Versioning property replacement patterns | High | 001001, 001002, 001004 |
| Version promotion/transition rules | High | 001005-001007 |
| Extension.* operation patterns | High | 002001, 002002, 002004 |
| ArmCustomPatch vs ArmResourcePatch | Medium | 002003, 002009 |
| ARM LRO header customization | High | 003001-003003 |
| ResourceNameParameter compilation | Critical | 004001 |
| Custom scalar for array constraints | Medium | 004002 |
| Compiler-dependent tasks | Blocking | 005001 |

### 4. Risk of Silent Failures
Without the skill, the agent can produce code that **appears correct but silently fails** (e.g., 004001 where augment decorator targets wrong property name). This is worse than an obvious error.

---

## Recommendations

1. **Always use the skill** for versioning tasks involving property replacement patterns or version transitions
2. **Always use the skill** for LRO customization — 0% accuracy without it
3. **Always use the skill** for extension resource definitions — specialized operation patterns required
4. **Simple versioning decorators** (`@madeOptional`, `@removed`, etc.) may be safe without the skill
5. **Basic ARM resource definitions** (define resource, child resource, custom action) may be safe without the skill
6. **Decorator and warning tasks** should always use the skill to avoid silent failures
